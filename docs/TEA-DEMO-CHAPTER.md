# 赛博小镇 · 第一章「第一杯生意」

状态：已接入可玩主线（tea.2）。独自试营、两次招募、主角批次指派、正式高峰与升级均已由真实接口跑通，见 [当前主线](TEA-MAINLINE.md) 与 [独立验收](REVIEW-TEA-CHAPTER.md)。下列时间表是体验预算，不是强制倒计时。

## 核心体验

**开店前做策略；开店后，同事全自动，自己半自动。雇佣分担具体工作，玩家从忙碌变得从容。**

“半自动”是一次指派一批工作，角色自动走到工位、执行、交付；玩家再决定下一批先处理哪个瓶颈。“全自动”是员工按开店前分工持续接活，不需要玩家再次点名。玩家不逐杯操作，也不需要操纵移动、按时机倒饮料或连点清台。

首章使用0→1→2名同事递进，最终仍为主角+2名员工，不增加人数上限。主角在无人负责的环节兼岗；这是本次新需求对原先“自己也全自动”和固定三人开局的修订。正式开店后不换人、不换备货、不换合同，玩家只指派自己的工作，不遥控同事。

## 约5分钟节奏

时间是正常操作的体验预算，不是强制等待。阶段靠真实行动和营业结果推进，可跳过演出；操作快约4分钟，初次摸索约5～6分钟。

| 时间 | 玩家做什么 | 自动发生什么 | 需要感受到什么 |
| --- | --- | --- | --- |
| 0:00–0:20 接手小店 | 看见目标，选择开门 | 镜头由招募街区移入自己的奶茶店，第一位顾客走来 | 立即知道今天要把这家店经营起来 |
| 0:20–1:00 独自试营 | 指派一次接待、一批制作；下一批先处理排队最长处 | 主角走位、完成所指派批次并交付；顾客正常等待或离开 | 自己能经营，但两边兼顾会忙；不是读教学 |
| 1:00–1:30 招第一位同事 | 在街区选择制作专长同事，放到制作位 | 招募后同事走向工位；新的试营自动制作 | “出杯交给他，我不用再盯制作” |
| 1:30–2:30 验证分工 | 只指派自己的接待/交付，观察剩余拥堵 | 制作同事持续自动处理；接待形成下一处可见瓶颈 | 招人确实少了一类操作；岗位配置有因果 |
| 2:30–3:00 招第二位同事 | 选接待专长同事，安排前台；主角改机动，选备货/策略 | 三人就位，预算实时显示 | 两个岗位有人接管，自己能专心调度 |
| 3:00–4:10 正式高峰 | 开店；需要时给自己一条支援指令 | 同事持续自动接单、制作、交付；主角执行所指派的支援批次 | 日常交给同事，决策留给自己；两位同事比一位明显轻松 |
| 4:10–5:00 收益与焕新 | 看前后差异，使用真实收益升级一次 | 正式记账发工资，招牌/门头焕新，员工庆祝 | 从“我在打工”变成“店在运转”，愿意继续下一场 |

前三段是无经济副作用的教学试营，不消耗正式机会；正式高峰复用80人、240模拟秒、72杯目标及预算。不能写死失败、成功或差异数字；若玩家的早期方案已高效，直接认可，减少纠错引导，不强行制造拥堵。

## 自己的半自动操作

主角只有一个当前任务批次，不可同时多处工作。点击有积压的工位即可指派，移动和执行由角色完成；一次最多3单或12模拟秒，到时把已开始的一单做完后待命。最多排下一批；重复点击不叠加加速、不多拿收入。界面优先突出无人接管或真正拥堵的岗位，两个按钮作为工位点击的兜底。

| 同事人数 | 同事持续负责 | 玩家主要决策 |
| --- | --- | --- |
| 0 | 无；教学客流小，主角可以兼岗完成完整订单 | 接待还是制作先做，哪边先积压 |
| 1 | 制作或接待中的一个完整岗位 | 自己处理另一端，体验被分担的工作 |
| 2 | 接待、制作及岗位内交付各自持续循环 | 主角何时支援、优先哪边；经营重心回到阵容和成本 |

同事越强，其岗位队列越短，玩家需要指派自己的频率自然下降。若两名同事已经能稳定完成日常，允许主角暂不支援；不能人为刷出额外杂务逼玩家点击。操作只是调度，不用反应速度弥补不合理的选人和库存。

## 接待流程与画面

`到店 → 前台排队 → 自动接单 → 等待饮品 → 自动制作 → 交付/收入 → 离店`

参考《潜水员戴夫》的开业前准备、岗位分工及可读服务动线，将顾客、订单、制作和交付的因果画出来；不照搬手动端盘、倒茶、磨芥末小游戏。奶茶店以柜台取饮为主，不额外增加堂食座位或清洁产能系统。员工交付后顺手整理台面可以作为短演出，不能变成每位顾客都要求玩家点击的新任务。

必须修正现有表现：待制作订单不画成已经做好的一排杯子；等饮品的顾客留在取饮区，出杯后真正取走饮品再离店；同一顾客有稳定身份，不能用不同人凭空替换排队状态；有哪位员工接单/制作，就由哪位员工做对应动作。所有工作、流失、技能和交付由真实模拟事件驱动画面。

参考资料：[官方游戏介绍](https://store.steampowered.com/app/1868140/DAVE_THE_DIVER/)、[开发者更新记录（包含交付接近顾客、员工服务等修复）](https://steamcommunity.com/app/1868140/allnews/?l=english)。这里借鉴的是服务流程呈现，具体操作以上述本游戏规则为准。

## 少文字

美术与交互由Claude沿用原会话实现，见 [少文字UI分镜](TEA-DEMO-UI.md)。Codex完成服务端指派时间线、章节、经济、客户端控制器与独立验收；dsh沿用原会话完成冻结类型、API薄封装及真实HTTP Agent实玩脚本。

- 每一步只留一句目标，建议不超过16个汉字，例如“先接待这批客人”“请位同事帮你出杯”“让小李接管前台”。
- 当前可操作的工位、角色或按钮发光；不同时高亮多个教学目标。完成一步直接进入下一步，不连续点“下一页”。
- 招募卡先露名字、擅长项、工资；三属性和技能说明按需展开。可读名称仍保留，不能只剩不明图标。
- 筹备先露岗位、备货、策略和预算/钱包两条数值；解释按需打开。自动同事与半自动主角有明确标识。
- 营业以场景为主，保留完成/目标、两端队列及库存。主角待命时才显示可指派提示，不用长日志挤占画面。
- 结算先露完成杯数、净收益、主要瓶颈和一个下一步。工资、利润明细、曲线、技能记录保留在“详细报告”内。

## 验收

1. 首次体验无需读规则，在约5分钟内经历一次“自己忙→同事分担→自动运转”的完整闭环。
2. 在相同客流、同一主角下，0/1/2名同事的必要指派次数和等待时长真实变化，不能只在文案上称更轻松；记录每种配置的实际数值。
3. 主角一次只执行一批，员工不需二次点名；连续点击不能复制订单、无成本提速或重复收入。
4. 营业中不换人、不改库存；暂停/加速/跳过不重复结算。失败仍付工资、练习零经济副作用。
5. 玩家能看懂顾客从排队到取杯离店，知道哪个岗位拥堵，并独立改一次阵容或岗位。
6. 第一次正式达标后升级，真实账本和外观同时改变；不靠新手必败或强制邀请同事推进。
