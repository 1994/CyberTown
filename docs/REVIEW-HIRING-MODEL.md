# 私人小镇与员工合同：第一阶段验收

本轮按最新定位先交付经营模型、雇佣大厅和员工流转，主线仍从手机领取救店任务。原策划文档作为素材；默认私人小镇、员工成长和可交易合同以用户后续要求为准。没有永久绑定；玩家可以培养员工自用，也可挂牌转让。

## 已实现

- 默认进入自己的小镇，真人世界位置按房间隔离；场景只展示镇主与本镇雇佣的分身。
- 雇佣大厅含候选、详情、我的员工和交易市场，支持触屏竖横屏。报价、金币、工资和经验均来自服务端。
- Lv1保洁/补货自动工作，60XP升Lv2后召回排班，180XP升Lv3解锁经理巡检。离线收入最多8小时；玩家仍半自动补位，员工全自动。
- 挂牌、撤单、购买、成交记录使用真实金币与持久化归属。挂牌暂停用工；成交保留等级经验，卖家支付5%手续费，系统有对应流水。
- 报价检查、员工上限、同源限制、正在营业/派工保护、重复请求与并发抢单均由服务端执行。
- 商业街、娱乐街和四个探索据点接入180×132米地图；保留短距离首店动线和可选招募。首店经营结束不代表商业帝国已完成。

## 验收证据

真实时间的界面流程见 [natural-transfer.json](../artifacts/hiring-model/natural-transfer.json)：签约120金币、自然派工升到Lv2、召回、挂牌/撤单/重新挂牌，另一账号250金币买入，卖家实际到账237、手续费13；60XP保留，卖家过去36金币经营收益保留，买家可在奶茶店筹备中选入。

Go全量、私人房间与经济并发检查、交易回滚检查和前端规则检查分别保存在 [go-tests.txt](../artifacts/hiring-model/go-tests.txt)、[economy-race.txt](../artifacts/hiring-model/economy-race.txt)、[market-tests.txt](../artifacts/hiring-model/market-tests.txt)、[web-checks.txt](../artifacts/hiring-model/web-checks.txt)。地图另有52条路线的独立碰撞采样检查。

浏览器回归原始记录为 [e2e.txt](../artifacts/hiring-model/e2e.txt)，触屏复测为 [touch-recheck.txt](../artifacts/hiring-model/touch-recheck.txt)。第一次触屏功能检查完成后，Playwright在关闭context时出现文件流长度错误；测试过程中修改了截图设置，随后固定源文件在独立服务复测通过，未把这个基础设施错误当成游戏功能通过。

最终19个独立功能场景均有通过记录，汇总见 [acceptance.json](../artifacts/hiring-model/acceptance.json)：主批次17通过、2失败，触屏和断网分别复测通过，并非宣称一次运行19项全绿。断网用例在同时运行其他图形检查时超过60秒且录制文件收尾出错；停止并行图形负载后，沿用原测试与原60秒限时，17.2秒通过，见 [offline-recheck.txt](../artifacts/hiring-model/offline-recheck.txt)。

后期三段经营测试通过私有测试库把已派工作的时间前移，再由真实服务端同时结算经验、收入和流水，随后召回员工；这与自然培养验收分开，既不向试玩库写数据，也不只凭空设满级而漏掉培养收入。

正常画质检查见 [normal-visual.json](../artifacts/hiring-model/normal-visual.json)，通过真实步行查看商业街与娱乐街、全图鸟瞰、签约确认，并验证未点考察/未签约不会自动领钱或扣款。所有浏览器测试使用独立数据库；试玩库保留验证见 [preview-preservation.json](../artifacts/hiring-model/preview-preservation.json)。企业身份只验收既有SPI fixture，未声称连接真实企业内网。

## 后续阶段

本轮没有交付互访入口、多店集团调度或随着等级实际长出的宏伟城市。相应数据基础不等于完整玩法。下一阶段再深化经理代管与养成表现，然后做同事小镇互访和城市建设；长线价格、离线收入与城市门槛仍需结合后续章节调参。
