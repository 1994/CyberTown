# 赛博小镇 · 主线交付与独立验收

本轮按用户要求将游戏集中为招募街区和奶茶店经营两个场景，保留赛博夜景、黄青霓虹、工业建筑与卡通面具人物。附件《同事商业街》仅作为策划资料，其中的代理任务说明不替代用户指定的分工。当前只做清晰主线，未增加支线。

## 玩家目标与闭环

玩家接手街角奶茶店，先组建三人队，验证经营方案，再在午间高峰完成至少72/80杯，靠收益将门店升至三级。核心操作都发生在营业前：选人、排岗、备货、策略；营业自动进行，报告给出下一次可执行的改进建议。

**招募2人 → 筹备岗位/备货/策略 → 免费试营业 → 看瓶颈并调整 → 正式达标 → 收益升级。**

筹备、营业和复盘是经营场景的三个状态。招募解决产能和技能配合问题；真实玩家分身须主动公开招聘，演示人物有明确标签，没有同事也能使用系统员工与演示角色完成主线。完整规则及六阶段目标表见 [主线设计](TEA-MAINLINE.md)。

## 界面验收

最终独立执行 `npm run test:e2e`：**2 passed（19.8秒）**。桌面1440×900与手机390×844、横屏844×390的完整闭环通过，场景切换无页面异常。桌面普通阵56杯、互补阵80杯；手机默认阵61杯。桌面还验证了服务端已结算但客户端断网的场景：第二次提交沿用同一幂等键，返回同一记录，未重复扣费。

新增的主线验收断言通过：首次目标与招募/带队操作对应，筹备指向试营业，未正式达标不能升级，报告给出换人/正式/升级建议，三级门店与正式达标同时满足后显示主线完成。成功重试会清除旧“结果未确认”，库存恰好用完与真实断货流失有区别。报告内“下一步”和主线条分别呈现，未覆盖营业指标。

独立复核了桌面、手机和横屏截图，名字、岗位和队列可见，底部开业按钮可达。此前发现的场景标签DOM卸载竞争已由Claude替换为场景内文字精灵修复。端到端流程使用低特效模式保证复测稳定，另在Orca正常画质的992×674浏览器完成招募→筹备→免费营业→报告，完成61杯，钱包保持2000，报告明确建议按瓶颈调整；[实机读取结果](../artifacts/tea-mainline/normal-preview.json)。
